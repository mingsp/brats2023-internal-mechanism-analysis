# PPTT 主文图重构与 TransUNet 机制复现设计规格

## 1. 目标

本轮只完成两个相互支撑的任务：

1. 使用正式实验数据重构三张主文图，使读者直接看出“终点指标遗漏了什么、PPTT 发现了什么、过程发现能否预测干预后的输出变化”。
2. 在 TransUNet 上执行一次独立的“验证集发现候选—首次 test 干预前锁定—测试集反事实验证”，检验 PPTT 能否跨架构产生可复现的机制候选。

本轮不修改 V7 的患者、阈值、匹配规则、过程事件或结论。V7 保持 `INSUFFICIENT_NETWORK_COVERAGE`，完整 7×7 矩阵进入补充材料。CAM 与 LayerCAM 不进入 PPTT 方法和干预定义。

## 2. 第一性原理：方法成功必须提供四种能力

### 2.1 保留终点无法恢复的信息

终点混淆矩阵只给出像素状态的边缘分布。PPTT 必须保留同一像素跨节点的联合身份，才能区分修正、破坏、稳定错误和错误重编码，并通过完整轨迹判断变化是否持续进入最终输出。

### 2.2 把过程差异变成可见对象

图件不能只展示曲线或彩色分割结果。每个变化像素必须具有明确事件含义，读者能够沿相同病例、相同切片和相同像素观察状态如何改变。

### 2.3 让过程发现预测反事实行为

仅能描述节点差异的方法仍属于观察诊断。机制证据要求 PPTT 在独立验证数据上提出结构候选，并在测试干预前固定变量、算子、患者、统计阈值和失败条件；随后检验必要性、恢复性、区域特异性和剂量关系。

### 2.4 给其他研究者可执行的诊断指引

方法输出不能停留在“某层重要”。对每个模型应产生可复用的过程诊断：决策在哪个区间形成或丢失、涉及哪类像素事件、是否持续进入输出、对应哪个可检验结构变量、干预后是否复现。其他研究者应能据此提出结构设计、模块替换、鲁棒性检查或失效定位假设，而不是照搬某个 U-Net 结论。

## 3. 三张主文图

### 3.1 图 1：PPTT 计算流程

**科学问题：** PPTT 如何把冻结分割网络的中间特征转换为同一像素的决策形成过程？

**单向数据流：**

```text
MRI 与冻结网络
→ 八个有序检查点
→ 输出约束的像素状态
→ 同像素完整轨迹
→ 相邻转移事件与持续形成深度
```

**构图要求：**

- 使用一例真实 MRI、真实节点状态和真实最终分割，不使用合成热图。
- U 形网络只是适配示例，PPTT 模块位于网络节点输出之后，不把跳接画成方法本体。
- 八个节点状态保持同一病例、同一切片和同一视野。
- 只突出一个真实像素或一个小像素群的状态轨迹，用青色表示持续纠正、橙色表示破坏、紫色表示错误重编码。
- 删除现有图底部彼此分散的折线、柱状和空间图，只保留转移张量、事件分解和持续形成深度三个输出符号。
- 图内不出现 CAM、F/G、响应熵、特征范数或实验效应值。

**十秒读图结论：** PPTT 追踪的是同一像素贯穿网络节点的决策变化，而不是节点热图或独立性能值。

**科学问题：** 终点 Dice 是否足以判断两个模型经历了相同的内部决策过程？

**面板 A：患者级关系图。**

- 使用 750 个正式患者—种子配对样本。
- 横轴为终点肿瘤 Dice 绝对差异，纵轴为全路径过程距离。
- 用浅灰色带标出终点差异不超过 2 个百分点的描述性区域。
- 三个种子使用相同色根的不同标记形状，不依赖颜色区分。
- 直接标注：`86/750` 个样本位于该区域，其过程距离中位数为 `0.163`。
- 代表病例继续采用预声明中位规则得到的 `BraTS-GLI-00734-000`，不得按视觉显著性重选。

**面板 B：三项总体效应森林图。**

- 中部正确像素破坏：`+4.087 [3.615, 4.593]` 个百分点。
- 后期持续净修正：`+18.855 [17.855, 19.852]` 个百分点。
- 终点肿瘤 Dice：`+4.963 [4.538, 5.397]` 个百分点。
- 三项共用同一百分点坐标和零参考线。

**面板 C：全节点像素命运轨迹。**

- 两行分别为有跳接和无跳接 U-Net，八列为全部节点。
- 所有面板使用同一病例、同一切片、同一病灶裁剪框。
- 不再大面积填充分割类别。真实肿瘤边界使用白色细线，状态未变区域使用低对比灰色轮廓。

- 第一节点只显示基线状态，后七节点叠加相邻转移事件。
- 图例只保留三个事件类别，避免重复解释肿瘤标签颜色。

**十秒读图结论：** 终点只相差约 5 个百分点，但后期持续修正相差约 19 个百分点；模型通过不同像素决策路径形成终点预测。

### 3.3 图 3：从过程候选到反事实验证

**科学问题：** PPTT 定位的稳定过程候选能否预测原模型受到内部干预后的输出变化？

**代表病例：** 使用预声明多变量中位效应规则得到的 `BraTS-GLI-00680-001_78`，不得改为最大效应病例。

**面板 A：目标定义与四条件反事实。**

- 左侧在真实 MRI 病灶放大图上仅描出固定持续纠正像素集合。
- 右侧按 `Clean → Corrupt → Target Restore → Matched Control` 排列同一裁剪区域。
- 固定目标集合中保持正确的像素使用低饱和青色，干预后丢失的像素使用橙色，目标恢复后重新正确的像素使用高饱和青色。
- 真实肿瘤边界使用白色细线，非目标区域降为灰色。
- 每个条件直接标注保持率：`1.00 → 0.44 → 0.65 / 0.53`。
- 使用统一的放大框，不为不同条件选择不同裁剪区域。

**面板 B：剂量关系。**

- 横轴为目标路径恢复比例，纵轴为持续纠正保持率。
- 三个种子使用不同点形和线型，置信区间使用同色浅带。
- 直接在线尾标注种子，不使用独立大图例。

**面板 C：干预效应森林图。**

- 按必要性、恢复性和区域特异性分组，每组显示三个种子及 95% 置信区间。
- 使用原始百分点作为主坐标，配对标准化效应量进入图注或数据表，不与百分点混轴。
- 显示零参考线和每个种子的有效患者数。

**十秒读图结论：** 破坏结构变量使 PPTT 定位的持续纠正像素丢失；只恢复目标区域比恢复等量对照区域更有效，且恢复比例增加时效果单调增强。

### 3.4 补充图：V7 全网络覆盖审计

V7 不承担正文强机制图。补充图并排显示：

1. 7×7 特异恢复效应矩阵；
2. 7×7 可评估患者数或目标像素数覆盖矩阵。

灰色表示不可评估而不是零效应。图注必须写明最终状态为 `INSUFFICIENT_NETWORK_COVERAGE`，不得仅展示正向单元。

### 3.5 图件统一规范

- 所有数值、病例和图像只来自正式 `Parquet/JSON/NPZ`；不使用图像生成模型。
- 输出中英文 PNG、PDF 和图源 JSON；PNG 为 600 dpi，PDF 尽可能保留矢量文字与图元。
- 统一使用白色背景、深灰文字、安静网格和色盲友好配色：青色为纠正/恢复、橙色为破坏、紫色为错误重编码、蓝灰为中性参考。
- 不依赖颜色单独传递信息，配合轮廓、点形、线型和直接标签。
- 代表病例必须由预声明中位规则选择，图源 JSON 记录病例、切片、规则、数据文件哈希和全部数值。
- 契约测试检查同病例同切片、节点完整性、数值一致性、空值语义、分辨率、文字遮挡和像素非空。

## 4. TransUNet 前瞻性机制复现

### 4.1 唯一研究问题

> PPTT 能否在不复用 U-Net 候选结论的情况下，从 TransUNet 的验证集过程轨迹中发现一个稳定候选，并预测该候选结构变量在测试集干预后的像素行为？

该实验验证的是方法生成机制假设的能力，不要求 TransUNet 复现 U-Net 的 `up1->up2` 结论。

### 4.2 数据隔离

1. 使用现有三种子 TransUNet 权重与正式观察器。
2. 单独生成 TransUNet 验证集 PPTT 轨迹；验证集只用于候选选择和阈值可行性审计。
3. 在任何 test 干预前锁定候选、结构变量、空间算子、剂量、匹配规则、统计阈值、患者有序清单和代码哈希。
4. test 只执行一次正式确认；候选失败、覆盖不足或效应失败均保持原状态，不换候选、不降低门槛。

### 4.3 候选空间

候选空间在读取验证结果前由 TransUNet 计算图确定，只包含预声明的 decoder 接收变量：

- Transformer/混合编码器进入 decoder 的瓶颈输入；
- 三个 decoder block 实际接收的 ResNet skip 输入；
- 与八个 PPTT 检查点相对应的接收节点。

候选不是任意通道、任意注意力头或结果后选择的空间位置。每个候选必须能够在模型代码中定位到唯一张量输入，并通过钩子恢复审计。

### 4.4 验证集候选选择

对三个种子使用同一预声明规则：

1. 过程事件限定为输出锚定的持续肿瘤像素纠正；
2. 候选区间必须在至少两个种子上具有足够患者和目标像素覆盖；
3. 持续净修正方向必须跨种子一致；
4. 按跨种子标准化效应的最小值排序，平局按网络拓扑顺序选择；
5. 最多选择一个候选。

若没有候选通过，状态记为 `NO_REGISTERED_TRANSUNET_CANDIDATE`，不得进入 test 干预。该结果属于方法边界，不是执行失败。

### 4.5 干预设计

复用 V6 的最小因果闭环，但干预变量来自 TransUNet 自身候选：

1. `Clean`：原始前向。
2. `Corrupt`：对候选分支张量执行锁定空间循环平移，逐通道保持激活值多重集合。
3. `Target Restore`：在 PPTT 定位的目标像素映射区域恢复同一输入的干净激活。
4. `Matched Control`：恢复等量、同类别、同边界距离和同激活范数分层的非目标位置。
5. `Dose`：恢复比例固定为 `0, 0.25, 0.50, 0.75, 1.00`。

主要结局为原模型最终输出在固定持续纠正像素集合上的真实类别保持率。观察器只用于候选定位，不作为干预结局。

### 4.6 成功门控

至少两个模型种子同时满足：

- 必要性：破坏后目标保持率显著下降；
- 恢复性：恢复目标结构变量后保持率显著回升；
- 区域特异性：目标恢复显著高于等量匹配对照；
- 剂量关系：恢复比例增加时患者级总体方向单调；
- 算子审计：完整恢复误差不超过 `1e-6`，钩子数量恢复，空间平移保持通道多重集合；
- 最低标准化效应与多重检验规则在 test 干预前写入协议锁。

通过后允许写“PPTT 在第二种 U 形架构上前瞻性产生并验证了一个架构特异的过程—结构候选”。不得写成不同架构共享同一机制或恢复了 TransUNet 的唯一真实因果机制。

## 5. 对其他研究者的价值与交付形式

### 5.1 过程诊断报告

对任意接入模型，PPTT 输出统一报告：

- 节点与区间的决策状态轨迹；
- 修正、破坏和错误重编码的类别与空间分布；
- 持续正确、持续错误和形成深度；
- 终点相近模型之间的全路径过程距离；
- 通过验证集发现的结构候选及其 test 干预状态；
- 覆盖不足、观察器不可靠或候选不存在等失败原因。

### 5.2 可执行研究指引

PPTT 不直接规定应增加哪个模块，而是把结构改进问题转化为可检验假设：

- 若中部正确像素破坏集中，可检查下采样、瓶颈压缩或跨尺度对齐造成的信息丢失；
- 若错误重编码集中，可检查类别边界混淆和不同尺度特征冲突；
- 若后期持续修正依赖特定结构变量，可在不改变其他路径的条件下验证该变量的空间对齐与信息保留作用；
- 若终点性能相近但过程距离较大，可进一步比较鲁棒性、跨域稳定性或失败病例，而不能仅按 Dice 选择模型；
- 若候选无法通过干预，应停止机制主张，并把结果保留为过程诊断而非因果解释。

### 5.3 可复用接口

代码应提供：模型检查点适配接口、观察器准入接口、转移与谱系计算接口、验证集候选选择器、协议锁、干预运行器、结论门控和图件生成脚本。新增模型只需声明有序空间节点和可干预结构变量，不需要改写 PPTT 的转移数学定义。

## 6. 对抗式审查

| 质疑 | 设计中的回答 | 仍保留的边界 |
|---|---|---|
| 只是线性探针加混淆矩阵 | 联合转移保留端点边缘无法恢复的同像素配对，完整轨迹保留相邻张量无法恢复的持续性 | 观察器状态仍是受控读出，不是唯一隐含语义 |
| 图件是挑最好看的病例 | 图 2、图 3 均使用预声明中位规则，全部总体效应同时展示 | 单病例只用于空间示例，结论来自患者统计 |
| U-Net 跳接专用方法 | TransUNet 候选由其自身验证集轨迹和计算图产生 | 仍只覆盖一个数据集和二维设置 |
| 观察相关不等于模型使用 | 候选在 test 上接受必要性、恢复性、特异性和剂量验证 | 只支持锁定变量和算子范围内的干预忠实性 |
| V7 失败后换实验挽救 | V7 保持原门控；TransUNet 是独立架构、独立协议和前瞻验证 | 不把 TransUNet 结果反写为 V7 通过 |
| 方法不能指导后续研究 | 输出明确的过程瓶颈、事件类型、空间区域、结构候选和失败状态 | 结构改进是否提高泛化仍需独立训练验证 |

## 7. 时长与资源估计

实际基线：V5 TransUNet 三种子并行完成 750 名 test 患者迁移约 55 分钟；V6 U-Net 三种子 750 例候选干预约 1 小时。TransUNet 干预前向更重，并需要新增验证集候选发现和结构变量钩子。

| 阶段 | 预计耗时 |
|---|---:|
| 三张图脚本重构、双语输出和视觉契约测试 | 4–6 小时 |
| TransUNet 计算图变量核对、协议与失败测试 | 2–3 小时 |
| 验证集三种子轨迹生成与候选选择 | 1–2 小时服务器墙钟时间 |
| 干预算子适配、真实病例 smoke 和显存检查 | 2–4 小时 |
| test 三种子正式干预 | 并行 2–4 小时；顺序执行约 6–10 小时 |
| 汇总、统计门控、图件与审计 | 1–2 小时 |

若三种子可稳定并行且验证集存在候选，完整工作预计为 `10–16 小时`，其中正式服务器长跑约 `2–4 小时`。若 TransUNet 钩子需要改造 vendor decoder 或三进程显存不足，总耗时可能为 `14–20 小时`。正式长跑超过 2 小时时，只提供完整启动与监控命令，由用户决定何时启动。

结果存储只保存离散状态、目标掩膜、条件结局和审计信息，不保存每次前向的完整激活张量，预计新增空间低于 5 GB。SSH 地址、凭据和其他隐私信息不得写入脚本；服务器连接与资产路径通过本地 SSH 配置、环境变量或未提交配置维护。

## 8. 完成标准

1. 三张主图均通过十秒读图自查，且每张图只回答一个核心科学问题。
2. 图 2 的 `86/750`、`0.163`、`4.087`、`18.855`、`4.963` 和 `3.80×` 与正式数据逐项一致。
3. 图 3 使用固定中位病例，并同时展示必要性、恢复性、区域特异性和剂量关系。
4. V7 保持覆盖不足状态并在补充图中完整显示空值与覆盖。
5. TransUNet 候选在 test 干预前完成内容寻址锁定，或明确记录无候选并停止。
6. 正式 test 结果不触发候选、阈值、患者、变量或算子修改。
7. 方法输出能够形成面向其他研究者的过程诊断报告和可执行研究指引。
8. 全量测试、图件契约、结果清单、隐私扫描和主张审计全部通过。

## 9. 非目标

- 不修改分割模型以提高 Dice。
- 不把 CAM、SHAP 或特征响应加入 PPTT。
- 不重新解释或挽救 V7。
- 不声称完整证明全网络真实因果机制。
- 不在本轮增加第二数据集或三维网络；这些属于冲击顶级期刊的后续广度验证。
